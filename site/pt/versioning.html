Versionamento Semântico Preditivo

O CCCP garante Versionamento Semântico determinístico (SemVer 2.0.0) calculado diretamente dos sinais dos seus commits, projetando previsões imediatas de release e registrando o progresso do desenvolvimento contínuo.

1. Os Dois Estados de Versão

A. Versão de Release Limpa

Quando o commit ativo corresponde exatamente a uma tag anotada de release do Git:

MAJOR.MINOR.PATCH
Exemplo: 2.1.0

B. Versão de Desenvolvimento Preditiva

Ao trabalhar em commits ainda não lançados entre tags, o CCCP projeta a versão de release prevista e anexa metadados de telemetria no arquivo VERSION:

<VERSAO_ALVO>-dev.<COMMITS_A_FRENTE>+<DATA>.<HASH_CURTO>
Exemplo: 2.2.0-dev.14+20260921.233189a

2. Regras de Elevação de Versão & Diretivas

Sinal do Commit Impacto no SemVer Significado & Diretiva Partidária
Marcador ! ou BREAKING CHANGE: MAJOR (X.0.0) Mudança revolucionária de paradigma; quebra de contratos de API
feat: ou feat(escopo): MINOR (x.Y.0) Avanço industrial para a Pátria; nova funcionalidade retrocompatível
fix:, perf:, refactor:, chore: PATCH (x.y.Z) Manutenção de rotina; reparo de sabotagens ou defeitos no maquinário

3. Criando Tags de Release (`cccp tag`)

Quando concluir uma etapa do plano, promova sua branch de desenvolvimento para uma versão estável oficial: 

# Promover para a próxima versão calculada automaticamente:
cccp tag

# Promover para versão explícita:
cccp tag 2.3.0

# Definir título personalizado e anotação:
cccp tag --title "Lançamento Vostok" -m "Conformidade automatizada estabelecida"
☭ Garantia de Proteção da Ordem nº 227

O comando cccp tag bloqueia execuções com árvore de trabalho suja e garante que o CHANGELOG.md e o VERSION estejam perfeitamente sincronizados antes de aplicar as tags no Git.
