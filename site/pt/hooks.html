Pelotão de Git Hooks & Automação

O CCCP atua como um comissário automatizado para o fluxo do seu repositório Git, bloqueando commits fora do padrão antes que entrem no versionamento e sincronizando changelogs em cada push.

1. Os Quatro Hooks Padrão

Nome do Hook Ciclo de Disparo Aplicação & Ação Automatizada
commit-msg Durante git commit Valida a sintaxe conforme Conventional Commits; exibe dicas corretivas imediatas.
post-commit Após commit concluído Sincroniza o CHANGELOG.md e atualiza a versão preditiva de desenvolvimento no VERSION.
pre-push Durante git push Verifica se as tags enviadas correspondem aos arquivos VERSION comitados e bloqueia push indevido.
reference-transaction Durante git tag Intercepta a criação de tags locais para impedir que apontem para estados de desenvolvimento sujos.

2. Inspecionando Hooks (`cccp hooks`)

O CCCP conta com um inspetor embutido para auditar e verificar diferenças (diff) nos hooks instalados:

# Auditar hooks instalados quanto à sincronização de versão:
cccp hooks audit

# Exibir diff unificado em relação aos modelos padrão (detecta Husky ou customizações):
cccp hooks diff

3. Automação Pós-Push & Scripts Customizados

Executar cccp push inicia o ciclo pós-push, permitindo scripts personalizados e ações automáticas de sincronização: 

# Enviar ao repositório remoto e disparar hooks pós-push:
cccp push origin main

Ordem de Descoberta para Scripts Pós-Push

  1. Caminho definido na variável POST_PUSH_HOOK ou no .cccprc
  2. Script compartilhado do projeto em .cccp/hooks/post-push
  3. Script local do desenvolvedor em .git/hooks/post-push.local
★ Sincronização Pós-Push Automatizada

Ative a sincronização automática de tickets e diretrizes de agentes sempre que um push for bem-sucedido:

cccp config post_push_sync "tickets,agent"
